语言模型接收到的不是完整汉字或英文单词，而是 tokenizer 产生的 token ID。相同文本在不同词表下可能对应不同长度，因此上下文预算应按目标模型的 tokenizer 计算，不能固定使用“一个汉字等于一个 token”的估算。

## 注意力究竟在计算什么

输入经过 embedding 后得到向量序列，再投影为 Q、K、V。缩放点积注意力可以写为 `softmax(QKᵀ / √d_k)V`：Q 与 K 的匹配决定信息聚合权重，V 提供实际被聚合的表示。权重描述的是当前层的计算关系，不能直接当作模型推理原因的完整解释。

在自回归生成中，因果掩码阻止当前位置读取未来 token。位置编码补充序列顺序信息；前馈网络、残差连接和归一化共同组成计算块。多头注意力让不同投影空间分别建模关联，但不是给每个头预先分配“语法”或“常识”等职责。

## 用一个生成过程串起来

假设输入是“订单金额为”，模型先处理整个输入，输出下一个 token 的分布。选择一个 token 后，把它加入序列，再预测下一步，直到结束条件满足。模型训练时学习的是序列上的预测目标，生成流畅不等于数据真实，业务金额仍应来自数据库或可信工具。

## 应用开发中的影响

长输入会增加预填充成本，长输出会延长逐 token 解码时间。优化时应分别测量输入长度、首 token 延迟和输出速度，而不是只看接口总耗时。普通全注意力的分数矩阵随序列长度平方增长，实际显存与速度还受注意力实现、缓存布局和模型架构影响。
