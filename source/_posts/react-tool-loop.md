ReAct 将推理与行动交替组织：根据任务选择行动，再依据观察修正下一步。应用中重要的是让真实工具反馈影响决策，而不是要求模型输出一段看似完整的思维过程。

## 一轮循环的数据边界

输入包括当前问题、必要状态与可用工具描述；模型输出工具名和参数；程序校验后执行；工具返回结构化结果。每个调用使用唯一 call_id，使结果能对应到正确请求。工具失败也需要结果记录，不能只在终端打印异常。

```text
任务状态 → 模型决策 → 参数验证 → 工具执行
    ↑                           ↓
    └──────── 结果或错误 ────────┘
```

例如查询“上月退款率”，模型先请求指标定义，再按口径查询分子和分母。如果分母为零，工具应返回明确状态，由系统决定无法计算；不能让模型把零除错误解释为退款率为零。

## 重试不等于重新思考

网络抖动可以在限定次数内重试，权限拒绝和参数不合法则需要改变请求或终止。若只是不断把相同错误送回模型，容易产生重复工具调用。记录错误类型有助于区分可恢复失败和业务拒绝。

对外展示可以保留执行步骤、工具状态和结果摘要，不必暴露内部推理文本。审计需要的是可核实操作及证据，不能把自然语言解释当作真实执行日志。
