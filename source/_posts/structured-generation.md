当模型输出要进入数据库、图表或任务调度器时，格式就是接口的一部分。仅要求“请返回 JSON”不能保证字段完整，更不能保证业务正确。需要把语法、结构和业务校验分开。

## 三层校验

第一层解析 JSON；第二层校验字段类型、枚举和必需项；第三层检查业务条件，例如开始时间不晚于结束时间、币种一致、指标是否允许计算。即使生成接口支持结构约束，后两层的业务职责仍不能省略。

例如模型输出 `{"metric":"refund_rate","value":12}`，12 可能是百分数，也可能是比例。契约应明确 unit、分子与分母口径，并由程序根据查询结果计算，而不是让模型自由填写。

## 失败后的有限修复

将具体错误返回模型可以辅助修正字段，但重试需要上限。修复后必须重新执行全部校验，不能只检查被修改字段。对于权限错误和不支持的操作，应直接拒绝，不应通过反复改写请求绕过限制。

```python
def validate_period(start, end):
    if start > end:
        raise ValueError("start must not exceed end")
```

该函数仅展示日期范围的业务检查，实际服务还需要完成解析、身份校验和异常响应。

## 版本管理

提示词、输出 schema 和消费端应协同发布。新增字段时明确默认值及兼容策略，并保存失败样本作为回归数据。不能只验证模型能够输出一个成功示例，就认为所有下游调用已经兼容。
