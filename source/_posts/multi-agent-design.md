专题：[Agent 系统](/study/#agent) · 知识点 28 / 38

多个 Agent 的价值应来自任务隔离、专用工具或可并行子任务，而不是角色名称。拆分会增加通信和协调成本，需要证明收益超过额外复杂度。

## 何时考虑拆分

查数需要受控数据库工具，报告需要组织语言，两者可以有不同权限与上下文。若单个 Agent 已经能稳定完成简单查询，就不必先引入主管、研究员和审查员等多个角色。

## 对比实验

使用相同问题集比较单 Agent 与拆分方案，记录成功率、工具错误、总 token 和延迟。观察提升来自能力隔离还是仅仅增加了模型尝试次数。

## 失败边界

子任务超时不能无限重启整个系统。定义部分结果是否允许返回、关键步骤失败如何传播。最终验收应检查结论依据和数据完整性，而非只看每个角色都输出了文字。
