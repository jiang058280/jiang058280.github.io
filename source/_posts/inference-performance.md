用户感知的响应时间由排队、输入处理、逐 token 生成和网络传输共同组成。只报告“每秒生成多少 token”，无法解释为什么高并发时首字迟迟不出现，也无法说明长文档问答为什么变慢。

## 拆开两种计算阶段

预填充处理输入上下文，解码逐步产生输出。KV Cache 复用历史 token 的键和值表示，避免每一步重复计算同样的历史内容，但缓存本身占用显存，长度和并发增加时也会增长。

PagedAttention 针对 KV Cache 的内存管理使用分块映射思路。它不等于无限上下文，也不能让任意长度请求免费运行。具体收益取决于模型、硬件和流量形态，应以实际服务压测为准。

## 指标要成组看

建议同时记录队列等待、首 token 延迟、输出 token 间隔、完整请求 P95、输入输出长度及失败率。平均值容易掩盖长尾，吞吐提升也可能伴随单个用户等待变长。

```text
端到端耗时 = 排队 + 预填充 + 解码 + 应用及网络开销
```

该分解用于定位瓶颈，不意味着各阶段在所有运行时中都能完全独立计量。流式输出能够改善首字反馈体验，但不会自动减少总计算量。

## 优化顺序

先减少无关上下文和无效工具调用，再按任务设置输出上限，随后比较批处理、并发和缓存方案。量化可能改变精度与性能，部署前要回归业务指标。不能只因为显存占用下降，就认定方案更快或更准确。
