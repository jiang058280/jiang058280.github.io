01 · 智慧教研平台

AI 应用开发

业务背景

平台面向全市中小学校，主要解决人工录题效率低、学科／题型／知识点标注口径不统一，以及题库数据难以支撑智能组卷和学情分析等问题。通过 AI 自动录入实现题目标签的标准化与自动化。

Python · FastAPI · PyTorch · Transformers · BERT · MySQL · Milvus · RAG · Docker Compose

个人职责

  • 负责历史题目和教学资料的数据清洗，处理重复数据、异常换行、题目切分、字段缺失及标签格式不统一等问题。
  • 将题干、选项、答案、解析、学科、题型和知识点整理为统一结构，为题库入库和知识检索提供标准数据。
  • 负责 PDF、DOCX、Markdown、TXT 教学资料解析与父子分块，整理学科、学段、年级、知识点、来源及访问范围等元数据。
  • 参与知识向量入库与版本管理，将资料、分块正文和业务状态保存至 MySQL，将子块向量及最小检索字段写入 Milvus。
  • 参与本地题库优先、资料向量召回、元数据过滤、来源引用和证据不足拒答调试，并通过 Bad Case 优化分块与检索参数。

工程关注点

区分结构化业务数据与向量检索数据的职责；围绕分块、召回、元数据与引用链路定位问题，避免把检索失败简单归结为模型能力不足。

团队成果

  • 清洗、去重并规范化历史题目录入语料 3.2 万余条，建立 12 学科、8 题型、320+ 知识点的三级标签体系，双人交叉标注一致率由 82% 提升至 95%。
  • 基于 bert-base-chinese 构建共享主干和 3 个分类头，三级联合准确率达到 89.8%，知识点 F1 较单任务基线提升 6.2pt。
  • 通过 SimHash 题目查重将重复率由约 6% 降至 0.5% 以内；完成 ONNX 与动态 Batch 优化，单题 P95 耗时由 216ms 降至 125ms。
  • 项目上线 3 个月累计自动录入试题 2.4 万余道，覆盖全市 10 余所学校，标准化标签支撑智能组卷与学情分析。

02 · 智能工单系统

RAG 应用开发

业务背景

客服团队新人培训周期长，老客服回答口径不统一、响应不及时，客户等待时间长。项目接入公司内部知识库，让 AI 根据客户问题自动生成规范答复。

Dify · RAG · Prompt Engineering · MySQL

个人职责

  • 负责公司内部文档清洗、去重和格式统一，将 200 余篇文档整理为适合知识库检索的语义分段。
  • 参与知识切分策略和元数据整理，根据文档标题、业务类型与内容边界进行分块。
  • 参与 Dify 工作流配置，串联意图识别、优先级判断、RAG 检索、自动回复和人工兜底流程。
  • 参与 Top-K、相似度阈值和提示词调整，约束回答范围、业务口径、输出格式及拒答边界。
  • 整理检索未命中、错误召回和回复口径不一致等 Bad Case，并根据人工评审结果优化知识库内容与提示词。

迭代方式

结合人工评审与检索问题归因，分别调整资料内容、切分策略、检索参数与提示词；在自动答复之外保留人工兜底。

团队成果

  • 工作流覆盖 6 类工单意图和 3 级优先级，意图识别准确率达到 95%，优先级判断与人工一致率达到 92%。
  • 清洗并切分内部文档 200 余篇，形成 3000 余个语义分段，检索命中率由 78% 提升至 91%。
  • 通过知识库、提示词和 Bad Case 持续迭代，将客服回复准确率由 85% 提升至 93%。
  • 约 60% 的常见问题工单无需人工介入，人工处理量下降约 40%，新客服培训周期由 4 周缩短至 2 周。

个人优势

  • 熟悉 MySQL 与 Milvus 的职责边界，理解离线知识入库、版本发布与在线问答的完整流程。
  • 掌握 LangChain、LangGraph、Function Calling、ReAct、LoRA/QLoRA 等技术，能够结合业务约束进行方案选型。
  • 重视回答可追溯性，能够通过来源引用、证据阈值和可靠拒答降低大模型幻觉风险。
