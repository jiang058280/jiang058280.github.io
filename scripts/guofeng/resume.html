02 · 问数·对话式BI（ChatBI）系统

Python · LangChain · LangGraph · A2A · MCP · Text2SQL · MySQL · Elasticsearch · FastAPI · SSE · ECharts

项目背景

公司面向有销售与运营数据分析需求的一个私有企业客户，开发ToB 对话式BI 系统。针对业务人员不熟悉SQL、临时取数依赖技术人员、固定报表难以满足灵活查询等问题，支持通过自然语言查询订单量、销售额等业务指标，并按时间、产品等维度进行汇总与对比。系统结合指标口径和只读查询约束，返回数据表、图表及结果说明，辅助业务人员完成日常取数和经营分析。

核心工作

  • 参与对话式BI 主Agent 开发，负责意图识别、启发式任务路由及Planning + ReAct 流程，根据步骤依赖关系串行或并行调用查数、归因和报告子Agent，并通过A2A 完成任务分发与结果汇总。
  • 参与查数、归因和报告子Agent 开发，使用LangChain create_agent 构建工具调用Agent，由底层LangGraph Runtime 维护消息状态、判断工具调用并驱动多轮“模型—MCP 工具—模型”循环。
  • 负责Text-to-SQL 链路开发，接入表结构、指标字典、SQL 安全校验和只读执行等MCP 工具，完成Schema 查询、SQL 生成、校验与查询执行。
  • 参与会话记忆功能开发，使用MySQL 保存短期对话、用户偏好及查询记录，支持服务重启后恢复上下文。
  • 使用FastAPI 和SSE 实现流式对话与ECharts 图表输出，并参与Docker Compose服务编排和接口联调。

项目成果（团队）

  • 搭建1 个主Agent、3 个业务子Agent，接入8 个MCP 工具，覆盖自然语言查数、指标分析、异常归因和经营报告生成流程。
  • 完成工具调用与任务链路评测，测试集任务完成率达到84.1%；建立参数缺失追问、Agent调用超时提示及并行步骤故障隔离等基础兜底机制，避免单个子任务异常导致整条分析链路中断。
  • 完成SQL 安全与数据计算测试用例，覆盖写操作、多语句、注释绕过、系统表访问和LIMIT 越权，测试范围内危险SQL 拦截率达到81%。
  • 通过任务并行和模型分级调用，单次对话平均减少1～2 次大模型调用；跑通异常指标定位、活动检索及历史案例匹配流程，归因误差控制在0.2 个百分点以内。

项目背景

公司客服团队新人培训周期长，老客服回答口径不统一、响应不及时，客户等待时间长。项目搭建智能工单系统，接入公司内部知识库，让AI 根据客户问题自动生成规范答复。

核心工作

  • 负责内部客服文档的清洗、去重和分块，整理业务类型、适用范围及来源等元数据，并完成Dify 知识库的导入与更新。
  • 使用Dify 搭建智能工单工作流，串联意图识别、优先级判断、RAG 检索、自动回复和人工兜底等节点。
  • 根据客服评审结果整理Bad Case，调整Top-K、相似度阈值和Prompt，优化检索准确率、回复口径及证据不足拒答。
  • 参与工单接口联调和流程测试，重点排查知识未命中、意图误判、回复不完整及人工转接失败等问题。

项目成果（团队）
